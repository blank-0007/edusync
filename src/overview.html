1The problem, made precise
P1
Availability. Lessons, drafts, submissions, exams and co-editing must work with zero network — for days, across restarts, on low-end devices. Offline is partial, not a boolean.
P2
Convergence. N devices + server must agree on identical state in any arrival order. Wall-clock last-write-wins silently destroys valid work.
P3
Exactly-once. Transport can only promise at-least-once, so submissions need client idempotency keys and immutable server-side attempts.
P4
Integrity without trust. Offline exam logs must be verifiable without trusting the device clock — and never auto-fail a student.
2The solution
L1
Local write first. Every action durably appends to a per-device op log and renders instantly; sync stays a background concern.
L2
Two data classes. Documents are Yjs CRDTs (lossless by construction); records are immutable server-validated facts (lossless by policy).
L3
Merge ladder. L0 identical → L1 CRDT → L2 field HLC → L3 domain policy → L4 Conflict Inbox. Never a silent overwrite.
L4
Delta + resumable sync. Batched push, state-vector pull, chunked uploads, jittered backoff, bounded queues, honest status UI.
Invariant No acknowledged edit is ever destroyed without a human-visible record.
