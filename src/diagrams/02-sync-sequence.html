The wire contract
Two idempotent endpoints

The advanced twist
Two offline editors, one document
A and B both edit doc_42 line 12 with no network. Neither knows the other exists.
A insert @12 "mitochondria is"
B insert @31 "the powerhouse"
Arrival order cannot decide the outcome: Yjs updates are commutative and idempotent.
merge(A, B) ≡ merge(B, A)
Both insert runs survive, interleaving is preserved — zero keystrokes dropped. A semantic conflict (two submitted versions) is frozen, never auto-chosen.
Why no keystroke is lost
Three independent guarantees
1 · Durable first. Every edit is an immutable op with a ULID + HLC, appended before the UI moves. Nothing is updated in place.
2 · Commutative merge. Text and lists merge by CRDT; records merge by per-field HLC with a deviceId tiebreak.
3 · Asserted convergence. Property tests replay random op permutations and require one identical state hash.
A genuinely contested edit never gets picked automatically — both versions are frozen into the Conflict Inbox, so “lossless” is a property of the system, not a hope.
